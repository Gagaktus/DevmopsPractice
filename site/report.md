## 2. Прогноз и факт
*   **Прогноз до поломки:** Я предположил, что упадет тест, проверяющий наличие CSS-файла, а последующие шаги сборки и сохранения артефакта не будут выполняться.
*   **Фактический результат:** Прогноз полностью подтвердился. Упал тест `test_stylesheet_exists` с сообщением `Missing stylesheet: missing.css`. Шаги `Build site` и `Save site artifact` получили статус Skipped.

## 3. Причина ошибки и остановка шагов
*   **Упавший тест:** `test_stylesheet_exists`
*   **Строка причины:** `Missing stylesheet: missing.css`
*   **Что произошло с шагами:** При падении шага `Run tests` (он вернул код ошибки), GitHub Actions по умолчанию остановил выполнение текущего job (задачи). Поэтому шаги `Build site` и `Save site artifact` не выполнились. Конвейер был остановлен на этапе тестирования, не допустив сборку и сохранение сломанного сайта.

## 4. Где выполнялись тесты и почему результат на GitHub
Тесты выполнялись на удаленном сервере (runner) GitHub Actions под управлением `ubuntu-latest`. Результат сохраняется на GitHub, потому что workflow запускается на стороне GitHub при каждом push. Это обеспечивает единую среду для всех участников (CI), гарантирует, что код будет проверен независимо от локального окружения разработчика, и сохраняет историю проверок.

## 5. Ограниченность проверок (Аудитория 301 -> 302)
Зеленый результат после смены аудитории с 301 на 302 не доказывает отсутствие ошибки, потому что автотесты проверяют только синтаксическую и структурную целостность (наличие тегов, файлов, ссылок). В тестах не заложена бизнес-логика или база данных с расписанием. Для компьютера строка "Аудитория: 302" является валидным текстом, даже если в реальности занятия проходят в 301. Тесты подтверждают, что сайт *не сломан*, но не гарантируют, что информация на нем *достоверна*.
